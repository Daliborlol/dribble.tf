# AGENTS.md: operational details for AI agents

## Build & Dev

- **Package manager**: npm (`yarn` not installed; use `npm run build`, `npm run dev`). `node_modules` was installed from the frozen `yarn.lock`, so add or upgrade no dependency, leave `yarn.lock` alone and never create a root `package-lock.json` (contract D15).
- **Worktrees**: link the shared modules once with `ln -s <main checkout>/node_modules <worktree>/node_modules`. `/node_modules` in `.gitignore` covers the link.
- **Build**: `npm run build` takes about 13 s (13.1 s at `b6688f4`). The main bundle is 2.81 MB, plus `hlextras_bg.wasm` 3.16 MB and `parser2_bg.wasm` 2.26 MB.
- **Type check**: `node_modules/.bin/tsc --noEmit -p .`. Avoid `npx tsc`, which can fetch an unrelated npm package named `tsc`. Exactly 10 errors are pre-existing and allowed: `BuildingCache.ts` x4, `ChunkedArray.ts` x3, `AnalyseMenu.tsx`, `DemoDrawing.tsx` and `UrlDemoNotice.tsx`. Any other error is new. `tsconfig.json` excludes `src/libs`, the wasm-bindgen glue.
- **Dev server**: `npm run dev` (Vite). It always installs the debug bridge `window.__dribble`; other builds install it only with `?debug=1`.
- **Converter config precedence**: `scripts/convert-config.json` overrides `scripts/convert-map.mjs` defaults when present, so map-conversion verification should pass explicit CLI flags or update the config if testing a changed default such as `chunk-grid`
- **Converter validation reruns**: pass `--chunk-grid 8` explicitly while `scripts/convert-config.json` still pins `chunk-grid=4`; `--skip-material-truth true` skips the slow VPK material scan when validating chunking/visibility output
- **Converter resume path**: `node scripts/convert-map.mjs ... --metadata-only true` reuses the temp BSP/VMF/GLBs/lightmaps to finish skybox, teleports, visibility, and `conversion.json` after a late-stage failure; skybox conversion still needs `vtf2img` importable from the `python3` on `PATH`
- **Headless browser validation**: Chrome remote debugging needs both `--user-data-dir=<tmp>` and `--remote-allow-origins=*`. Headless WebGL runs on this machine's iGPU through ANGLE EGL (`--use-gl=angle --use-angle=gl-egl --enable-gpu --enable-webgl --ignore-gpu-blocklist`). SwiftShader (`--use-angle=swiftshader --enable-unsafe-swiftshader`) is the CPU fallback at about 1 fps. `?perf=true` enables runtime perf logs. The validation harness is described under "Highlander validation tools".
- **WASM support**: Vite 5 handles `.wasm` via `new URL('./file.wasm', import.meta.url)` natively. No `vite-plugin-wasm` or `vite-plugin-top-level-await` is needed; wasm-bindgen's JS glue uses this pattern and has its own MIME-type fallback
- **Framework**: React + Three.js (react-three-fiber) + Zustand + Tailwind

## Highlander (9v9) mode

- **What it adds**: a second parse of each demo, the extras, feeds Highlander layers drawn on top of the base viewer. Players show cloak, decloak and disguises, uber, crit and debuff effects, crouching and the weapon they hold. Engineers get sentries, dispensers, teleporters and sappers. Every projectile type flies, with crit glows, explosions, tracers, flames and airblast, and sniper and wrangler dots draw.
- **POV and HUD**: POV gets the TF2 FOV and zoom, a scope overlay, class eye heights, placeholder viewmodels, a weapon HUD, death cameras and a chase camera. The HUD gets an objective panel for KOTH, payload, control points, stopwatch and tug of war, 9v9 player columns with badges, a medic panel, a Tab scoreboard, killfeed icons, a round banner and timeline markers. On the map, doors and trains move, kits show respawn rings, thrown lunchbox items fly and deaths leave markers. No TF2 game assets are used; everything Highlander adds is procedural placeholder geometry (contract D1).

- **Extras pipeline**: the base parse stays the committed `src/libs/parser2` binary, which is never rebuilt because its source is unpublished (D2). After the base parse resolves, its worker ends and the scene loads, `parseDemoAction` takes the file buffer the base worker handed back (`parsedDemo.takeFileBuffer()`) and calls `startHighlanderExtras` in `extras/loadExtras.ts`. `ExtrasWorker.ts` loads the second wasm module `src/libs/hlextras`, built from `../dribble-parser` branch `highlander`. It copies the file into wasm memory (`ExtrasInput`), detaches the JS buffer and calls `parse_demo_extras_input` with the base parse's `startTick`, `tickBase`, `ticks`, `intervalPerTick` and `playerEntityIds`, so the extras share the base cache ticks and player indices by construction (D3).
- **Hydration and alignment**: `hydrate.ts` moves every position into scene space (Source minus `parsedDemo.world.boundaryMin`) and builds the `HL` flag masks and the per-player and per-entity indexes. The main thread runs `checkAlignment` (16 sample ticks, base and extras positions within 4 units) and then stores the result as `useInstance().extras` with status `ready`, or sets status `error` with `misaligned: <reason>`. No result after 180 s is an error too. Loading a new demo cancels a running extras parse first, so the two parses never overlap (D4).
- **Extras cost**: on 1438891 (koth_product, 817 s, 50 MB) the extras parse takes about 1.1 s in the browser and holds 9.9 MB of typed arrays. On 1429417 (130k ticks) it takes 2.7 s and holds 39 MB, with a 213 MB wasm heap that ends with its worker.
- **Memory plan**: `extras/memory.ts` predicts the worker peak as `1.6 x fileMB + 126` MiB against `EXTRAS_BUDGET_MB` 600, or 300 when `navigator.deviceMemory` is at most 4. Over budget it drops optional groups by measured size, largest first: `drops`, `movers`, `flames`, `tempents`, `ragdolls`, `pickups`. It never drops `players`, `objectives`, `buildings` or `projectiles`, and when nothing fits it skips the extras ("demo too large for Highlander data on this device"). The largest local demo (123 MB) predicts about 322 MiB, so the default budget excludes nothing locally. `?hlExtrasBudget=<MB>` replaces the budget, and `?hlExtrasBudget=1` forces the skip path.

- **Toggle**: `settings.highlander.enabled`, the "Highlander features (applies on next demo load)" row. Its value at demo load decides whether the extras parse runs; otherwise the status is `disabled`. Turning it off at runtime unmounts every Highlander layer and widget at once, and turning it on again brings them back. A demo loaded while it was off has no extras, so it shows nothing more until the next load. The base-parse fallback described below runs either way. The other keys come in seven groups, `players`, `buildings`, `projectiles`, `sniper`, `pov`, `hud` and `map`, listed under "Highlander settings".
- **Query flags**: `?debug=1` installs the debug bridge in production builds, `?hlExtrasBudget=<MB>` replaces the extras memory budget, `?perf=true` logs runtime perf, and `?demo=<demos.tf id>` or `?demoUrl=<url>`, with an optional `?tick=`, loads a demo at a tick.
- **Keys**: `V` viewmodel, `I` cycles the disguise view, `4` chase camera, `[` and `]` previous and next timeline marker, `Tab` held opens the scoreboard. The base keys stay: `1` POV (shift for the previous player), `2` spectator, `3` RTS.
- **Degradation** (contract 3.9): every layer checks its setting and `extras.meta.available[key]` and draws nothing without data, and the base UI stays as it was. `ExtrasNotice`, bottom left, shows "Highlander data NN %" for at most 3 s while loading and then a dot, "Highlander data unavailable: <reason>" for 6 s after an error, "Highlander data off: <reason>" for 6 s when the memory plan skipped the file, and "Highlander data without <groups> (large demo)" when it excluded groups. `MapNotice` says "Map geometry for <map> is not available; players and objectives still play." or "Using <folder> geometry for <map>".
- **Old demos**: a player's local tables count only once a delta changes one of his local props. Without them, as on the bundled 6v6 sample or any demo recorded without `tv_transmitall`, the extras drop `view`, `ammo`, `scoring`, `itemCharge` and `sniper` for that player and read clip, rage, stickies and charge-begin values as unknown. Gate such values on `hasLocalTables(x, p)`. Eye heights then fall back to class heights and the base duck bit, and the scoreboard takes K/A/D from base deaths and `kill` events and damage and heals from `resource`. The 6v6 sample also has no `player_hurt` events, so `hurts` is empty, and no `fire`, `flames`, `uberDeployed`, `capStart`, `medicDeath` or `deflect` data; uber timing falls back to `HL.UBER` edges. All 133 local HL demos have live local tables for every player who played a class.

## Debug bridge and probes

- **Bridge**: `window.__dribble` (`src/utils/debugBridge.ts`) returns plain JSON. `getState()` reports `ready`, the parser status, the demo, playback (`tick`, `renderTick`), the scene (`mapLoaded`, `actorCount`, controls mode, focused entity), perf and downloads. Navigation: `goToTick(playbackTick)`, `setPlaying(bool)`, `setSpeed(x)`, `frames(n)`. Players: `listPlayers(tick?)`, `resolvePlayer(query)` and `focusPlayer(query)`, where a query is an entity id, a class such as `sniper` or `sniper@red`, or a name. Cameras: `setControlsMode('rts' | 'spectator' | 'pov', { player?, reset? })`, `getCamera()` and `setCamera(spec)`. Settings: `setSetting(dottedPath, value)`. Raw stores: `stores.useStore` and `stores.useInstance`.
- **`hl` entry points**: `hl.status()` returns status, progress, error and `meta` without convars. `hl.waitReady(timeoutMs = 90000)` is a Promise of the status once it is `ready`, `error` or `disabled`, and at the timeout it resolves with the current status instead of rejecting. `hl.at(tick?)` runs the probe `players.at` (every getter for every player). `hl.findTicks(kind, { limit, player, team })`, `hl.probe(name, ...args)` and `hl.probes()` follow. `hl.cameraNear(entityId, tick?, distance = 350)` returns an RTS camera spec behind and above a player, for `setCamera` or a plan step's `camera`.
- **Ticks**: `goToTick` takes a playback tick. The scene, `hl.*` and every probe use cache ticks, `renderTick = max(1, playback tick - 2)`, so playback tick = cache tick + 2. Probes default to the current renderTick. `hl_probe` reports use demo ticks: on 1434434, cache tick = demo tick - 94.
- **Probes**: `hl.probes()` lists 59, named `<feature>.<what>` and registered when their module loads.
  - `actors.registry()`, `players.at(tick?)`, `eyeHeight.at(tick?)`
  - `extras.plan(fileBytes?, seconds?, budgetMB?)`, `extras.load()`, `extras.summary()`, `extras.call(getter, ...args)`, `extras.restart(url, 'double' | 'cancel', waitMs = 3000)`

  - `buildings.at(tick?)`, `buildings.of(p, tick?)`, `buildings.draw(tickF?)`, `buildings.scene()`, `buildings.summary(stride = 1)`, `buildings.track(instance, from, to, step = 1)`, `buildings.tracerMuzzle(row)`

- **Probe rules**: `runHlProbe` never throws, and an unknown name or a thrown error comes back as `{ error }`. These need arguments: `fx.actor(entityId)`, `buildings.of(p)`, `buildings.track(instance, from, to)`, `buildings.tracerMuzzle(row)`, `pov.wallScan(p, from, to)`, `extras.call(getter)` and `extras.restart(url)`. Called without them in a sweep, `fx.actor` and `buildings.tracerMuzzle` return errors by design, and `map.props` carries a field `error: null` that is not an error.
- **Side effects and slow probes**: `extras.restart` fetches the demo again and restarts the extras parse. `viewmodel.debug` keeps its overrides until they are set back. `nameplates.cap(false)` turns the 12-plate cap off for the page. `mapdyn.surface(true)` re-runs both floor analyses synchronously. `pov.wallScan` and `pov.wallDistance` cast map rays without a BVH, and `buildings.summary()` scans every tick. A sweep over `hl.probes()` should skip these and `extras.call`.
- **findTicks**: `extras/findTicks.ts` knows 59 kinds (`FIND_KINDS`) plus `proj:<kind>`. It returns cache ticks in ascending order as `{ tick, player?, instance?, note? }`. `limit` defaults to 20, `player` (index p) and `team` (2 RED, 3 BLU) filter, and an unknown kind returns `[]`.
  - spy: `cloak` (`note: 'feign'` on Dead Ringer cloaks), `decloak`, `disguise`, `disguising`, `feign`, `backstab`, `headshot`
  - medic: `uber` (stock or unknown Medi Gun only), `kritz`, `quickfix`, `vacc`, `medicDrop`, `medicCall`
  - conditions: `crit`, `minicrit`, `burning`, `jarate`, `milk`, `marked`, `bonk`, `overheal`, `teleportedGlow`, `stun`, `gas`, `banner`, `zoom`
  - combat: `busiest`, `airblast`, `flamesOn`, `deflect`, `proj:<kind>` (`proj:7` flares, `proj:8` arrows, ...), `syringe`, `explosion`, `tracer`, `bullet`, `critBullet`
  - engineer: `buildStart`, `buildDone`, `upgrade`, `carry`, `redeploy`, `sapped`, `destroyed`, `teleported`, `wrangled`
  - objectives: `capStart`, `captured`, `capBlocked`, `capBroken`, `capping` (crossings of 0.5 progress), `cartMoving`, `cartReceding`, `overtime`, `roundWin`, `roundStart`, `setupFinished`, `respawnWave`
  - map: `doorMove`, `pickupTaken` (rows can name the taker and carry `note: 'thrown'`), `pickupBack`
  - Kinds are not memoised, so cache results per extras object. `findTicks('busiest')[0]` is the earliest of the busiest windows, not the busiest one.
- **In plans and evals**: actors move 2 to 5 frames after `goToTick`, so `await window.__dribble.frames(5)` before reading scene nodes. Early steps can run before the player GLBs load (`actors.registry` reports `modelVisible: null`), so poll. A camera set with `setCamera` survives later steps, and `setControlsMode('rts', { reset: true })` does not restore the default RTS camera while the controls are already in RTS, so come from a POV step. An eval can switch the POV player itself with `await window.__dribble.setControlsMode('pov', { player: entityId })`.

## Maps: the bsp-to-glb pipeline (Highlander maps)

- **Setup once**: `npm run setup:bsp` (`node scripts/setup-bsp-to-glb.mjs`) clones Hona/bsp-to-glb into `../bsp-to-glb` (from the main checkout: `/home/dalibor/programming/personal/bsp-to-glb`), checks out the pinned commit `7b7f7fc` on a local `dribble` branch, applies `scripts/bsp-to-glb/0001-*.patch` and `0002-*.patch` with `git am`, and runs `cargo build --release --locked` (about 25 s with `CARGO_BUILD_JOBS=4`). The patches make upstream work without game assets: unresolved cubemap-patch includes become warnings, multi-style lightmaps are composed (`--lightmap-styles`), NaN displacement alphas are sanitised, materials carry the texdata reflectivity (the flat albedo), and a `vtf-to-png` helper decodes PAK skybox faces.
- **Worktrees**: both scripts resolve `../bsp-to-glb` relative to the checkout, which is the wrong place in a worktree. Set `BSP_TO_GLB_DIR=/home/dalibor/programming/personal/bsp-to-glb` (or pass `--dir` / `--bsp-to-glb`).
- **Convert**: `npm run convert:bsp -- --bsp <tf/maps/map.bsp>` (`node scripts/convert-bsp.mjs`) writes `public/models/maps/<map>/{world.glb, lightmap.webp, visibility.json, map-meta.json, conversion.json, props.glb}` in 6 to 13 s per map and, when the BSP PAK ships the sky faces, `public/models/skybox/<sky>/`. No game assets are needed: surfaces get the compile-time average albedo as vertex colours, lit by the BSP's own baked lightmap. `--only-meta true` runs the same passes into the temp dir but writes only `map-meta.json`; `koth_product_final` uses it, because it keeps its older textured GLB and `conversion.json`. Other flags: `--map`, `--out-dir`, `--chunk-grid 4`, `--lightmap-format webp|png`, `--lightmap-floor 0.015`, `--meshopt true|false`, `--skybox-dir`, `--keep-temp true`, `--temp-dir`, `--overwrite-sky true`, `--props false`, `--bsp-to-glb <binary>`. `--temp-dir` defaults to the OS temp dir, so pass a dir on disk here (see the `/tmp` quota under Gotchas). Sky folders are shared between maps, so the converter never replaces an existing `public/models/skybox/<sky>/` whose pixels differ from the map's PAK faces: it writes them to `<sky>_<map>/` instead and prints the `MAP_SKYBOX_MAP` entry to add (`--overwrite-sky true` replaces the shared folder). The Node dependencies (`@gltf-transform/*`, `meshoptimizer`, `sharp`) come in through `@gltf-transform/cli`.
- **PAK static props (M2)**: after the `world.glb` write, `scripts/lib/static-props.mjs` converts each model in the BSP's PAK once with `bsp-to-glb --studio-*`, reads the static prop lump and writes `props.glb`. Instances use `EXT_mesh_gpu_instancing`, grouped by model, skin, sun-direction cluster and lighting pattern, plus one merged batch with exact lighting. Vertex colours are the PAK texture's average albedo, else `NEUTRAL`, times VRAD's per-instance vertex lighting from `sp_hdr_N.vhv` or `sp_N.vhv`; props without such a file borrow the light of nearby lit props. Unnamed, unparented, non-animated `prop_dynamic` entities with PAK models count (eruption's 54 rocks), and instances inside the 3D skybox are skipped (vigil 6, proot 139).
- **Props material and winding**: an `$alphatest` texture with at least 85 % passing texels draws opaque, a sparser one at its coverage, a blend at its mean alpha, and a cutout whose texture is not in the PAK at 0.55. The converter reverses every studio triangle (the VTX order is clockwise) and fails the props pass below 90 % drawn-triangle winding agreement; the shipped files reach 96.8 to 100 %. A failed props pass warns, removes `props.glb`, records `stats.props.error` and still writes `conversion.json`, without `files.props`. `conversion.json` gains `files.props`, `props { pak, stock, stockSolid, dynamic? }` and `stats.props`. Any reconversion without `--props false` rewrites `props.glb` and the `stats.props` timings.
- **Shipped maps**: ten bsp-to-glb folders: `cp_steel_f12`, `koth_ashville_final1`, `koth_proot_b5b`, `koth_warmtic_f10`, `pl_divulgence_b4b`, `pl_downfall_b13`, `pl_eruption_b15`, `pl_upward_f12`, `pl_vigil_rc10` and `tow_tetsudo_b10c`. All but warmtic have a `props.glb`, 0.1 to 4.3 MB each and 11.3 MB in total. PAK, stock and stock-solid prop counts: steel 5/1450/649, ashville 204/841/434, proot 57/353/117, warmtic 0/1078/473, divulgence 105/1487/426, downfall 43/1844/837, eruption 145 + 54 dynamic/1452/494, upward 42/1065/386, vigil 88/1428/409, tetsudo 473 + 2 dynamic/1242/511. `koth_product_final` keeps its textured GLB, plus `map-meta.json` and `files.meta` in its `conversion.json`. `getMapFolder` picks the longest `MAP_NAME_SEARCH_MAP` key that prefixes the demo's map name (`pl_vigil` -> `pl_vigil_rc10`), so another version of a converted map loads that geometry and `MapNotice` names it.
- **Runtime**: when `conversion.json` says `pipeline: 'bsp-to-glb'`, `World.tsx` loads `files.model` with the meshopt decoder plus the lightmap atlas (otherwise `textured_compressed.glb`), replaces materials by `material.userData.dribble.kind` (`src/highlander/map/bspMaterials.ts`, the rules any bsp-to-glb GLB such as `props.glb` reuses), and publishes brush-entity nodes by BSP model index in `useInstance().mapNodes` (`src/highlander/map/mapNodes.ts`). With `files.props` it also mounts `src/highlander/map/StaticProps.tsx` inside the rotated `world` group; it loads `props.glb` with the meshopt decoder, scales its colours by `map.brightness` and follows `map.staticProps`. `src/utils/mapAssets.ts` resolves the folder through `MAP_NAME_SEARCH_MAP` and caches one `conversion.json` fetch per folder. A missing file counts as absent and is cached as `null`, including the `index.html` that `npm run dev`, `vite preview` and the Netlify rewrite return with status 200; only a failed request is retried. Debug probes: `__dribble.hl.probe('map.status' | 'map.nodes' | 'map.meta' | 'map.props' | 'map.propInstances')`.
- **Map meta**: `src/highlander/map/mapMeta.ts` loads `map-meta.json` (raw Source units; scene = Source minus the demo's boundaryMin, `sourceToScene(p, parsedDemo.world.boundaryMin)`). `fetchMapMeta` requests it only when `conversion.json` lists `files.meta`: the ten bsp-to-glb maps and `koth_product_final` do. A folder whose `conversion.json` is absent, or answered with `index.html`, resolves to `null`, cached, with no request for `map-meta.json`; only a failed request stays uncached and retries. `isCachedMapConversion(map, request)` in `mapAssets.ts` tells those cases apart. `useMapMeta(map)` starts the fetch and `getLoadedMapMeta(map)` is the synchronous read for `useFrame` code: `MapMeta`, `null` when absent, `undefined` while unresolved. Never fetch per frame.
- **Map nodes**: World replaces `mapNodes` on every GLB reload, map change and `settings.scene.mode` change, so subscribe and re-apply transforms. `userData.dribble` holds `classname, targetname, parentname, team, bspModelIndex, entityIndex, origin, angles, localMins, localMaxs, hasGeometry, initiallyVisible, renderMode, startDisabled`. Render-mode-10 nodes stay hidden whatever the extras say unless their class is `func_door`, `func_door_rotating`, `func_movelinear`, `func_tracktrain`, `func_train` or `func_rotating` (contract 11.3).
- **Boundary overrides**: Highlander maps need no `OVERWRITE_MAP_BOUNDARIES` entry, because the demo's `m_WorldMins/m_WorldMaxs` equal the BSP's `world_mins/world_maxs`. The one exception is `tow_tetsudo_b10c`: its `plhud.nut` writes the tug-of-war push counter into the world entity's `m_WorldMins` and HUD counters into `m_WorldMaxs` (1428628 changes `m_WorldMins` 1572 times), so `MapBoundaries.ts` pins the BSP bounds and the converter camera from that map's `conversion.json`. Copy them again if the map is reconverted.
- **Known visual limits** (expected, not bugs): stock static props (crates, rocks, rails, oil drums, trains, most spawn doors and the payload cart) are TF2 game assets and are not rendered; only map geometry and the PAK props of `props.glb` are. Sticky traps rest on invisible crates, sniper dots and laser beams end in mid-air, rockets burst against nothing, sentries built on props float, and players stand on air. Examples on 1434434 (pl_vigil): at cache tick 6955 the BLU sniper UNC. redlix stands about 100 units above the visible floor and his sniper dot ends 109 units above it; at cache tick 9078 a sticky rests 167 units above the floor. VRAD baked the props' shadows into the lightmap, so dark patches can appear with nothing casting them, and a few gaps that a prop fills in game show the sky (pl_divulgence). Prop-only doors and setup gates keep their rendermode-10 collision brush as a node with `initiallyVisible: false`, which runtime code may show as the door's stand-in; rendermode-10 `func_brush` blockers and respawn visualizers are invisible walls in game and stay hidden. Overlays and decals (signs, arrows, cap letters), the 3D skybox (hidden, with the PAK props inside it) and light styles that toggle during a round are not rendered. The props ignore the sprp fade distances, so RTS overviews draw every PAK prop. Two stock skies are stand-ins: pl_divulgence `sky_badlands_01` uses `sky_dustbowl_01`, pl_upward `sky_upward` uses `sky_tf2_04`.

## Base parser fallback

- **Why**: the committed `src/libs/parser2`, which is never rebuilt, starts its cache only after 100 warmup packets with non-zero world bounds. On `tow_tetsudo_b10c` the map's `plhud.nut` writes HUD values into `m_WorldMins/m_WorldMaxs`. On 1429417 they stay zero for the whole demo, so parser2 returns 1 tick and no players. 1428628, the other tow_tetsudo demo, has zero world bounds until demo tick 3772, so parser2 would start 55.2 s late.
- **How**: when parser2's result has no timeline (at most 1 tick or no players), or starts `DELAYED_START_FALLBACK_SECONDS` (5 s) or more after the 100-packet warmup (the tick of the demo's 100th frame; locally only 1428628, 55.2 s late), `ParseWorker.ts` hands the file back. `AsyncParser.ts` then runs `parse_demo_cache_fallback` from `src/libs/hlextras` in a fresh worker. That is the fork's cache builder in `../dribble-parser` `src/lib.rs`, and it starts at the warmup end. The bounds come from the map's `OVERWRITE_MAP_BOUNDARIES` entry, else `conversion.json` `worldBounds`, else (after a delayed start) the world bounds parser2 read. `parserFallbackInfo.trigger` is `'no-timeline'` or `'delayed-start'`. If the fallback of a delayed start fails, parser2 parses the file once more (`{ lateStart: true }`) and the demo loads with parser2's late timeline; `parserFallbackFailure` records the error and `parserFallback` stays false. A failed no-timeline fallback fails the load. The progress shown continues from the previous pass and never falls back.
- **1428628**: it takes the delayed-start route. The fallback starts at demo tick 94 and covers the demo up to its last packet, where parser2 started at demo tick 3772 and left a 56.6 s tail without positions.
- **Output**: `parsedDemo.parserFallback` is true, `parserFallbackInfo` holds `map, trigger, reason, parser2, bounds, boundsSource, startedWithoutWorld, parseMs`, and the console warns once with `[parser] <reason> on <map>: parsing again with the fallback cache builder (<source> bounds)`. The output matches parser2 field for field, except that `positionScale` is 32 where parser2 uses 1024, `ticks` is the last written tick + 1 (93 fewer than parser2's header-sized timeline), and `endTick`, `endDemoTick`, `shots` and `activeWeaponDef` are missing. Nothing reads those four. Read each cache's own `positionScale`.
- **Highlander off**: both routes ignore `settings.highlander.enabled`, so with Highlander off 1429417 and 1428628 still load from the fork's cache, and contract 7.4 ("behaves as before S0") does not hold for those two demos.
- **Saved ticks on 1428628**: a moment's cache tick moved by +3678 against the pre-B2 timeline, so `?tick=` links and bookmarks saved before B2 point 55.2 s earlier, and tick-phase effects such as F1's uber-fading blink change phase.
- **Cost**: on 1429417, a 122 MB demo with 130k ticks, the failed parser2 pass takes 2.4 s and the fallback 3.5 s. The base caches hold 702 MB, 641 MB of it projectiles, which is 5.4 KB per tick against 5.0 KB with parser2 on 1428628, and the page peaks at 1.69 to 1.75 GB. On 1428628 the fallback adds about 2.5 s to the 3 s parser2 pass, and the page peaks at about 1.45 GB. A failed delayed-start fallback adds a third pass of about 3.1 s.

## Gotchas

- **Never push**: no `git push` anywhere, to any remote. This is a standing user rule. In multi-agent runs the main checkouts of `dribble.tf` and `../dribble-parser`, both on `highlander`, belong to the orchestrator, so work and commit in your own worktree and branch.
- **Unsigned commits**: gpg signing fails in this environment, so commit with `git -c commit.gpgsign=false commit`, end the message with the attribution line the session gives, and tell the user. `specs/highlander/STATUS.md` has the commands to re-sign later.
- **Heavy commands under one lock**: while several agents share the machine, run cargo and wasm-pack (with `CARGO_BUILD_JOBS=4`), `npm run build`, tsc, Node parses of demos, Chromium and dev-server sessions as `flock <lock file> <command>`. Call flock directly, because a flock around `bash -c` trips a Claude Code safety check. Never hold the lock while idle, and kill any server or browser you start. `/usr/bin/time` is not installed.
- **Memory gates**: swap is full, so check `free -m` first. Runs on 1428628, 1429417 and the long demos (1437285, 1432698, 1433815) need at least 3000 MB available. parser2 in Node peaks at 2.3 GB on 1433815.
- **/tmp quota**: `/tmp` is a tmpfs with a per-user quota of about 5 GB that every agent shares. It filled before, and EDQUOT broke builds and lost Bash output. Put harness outputs, `TMPDIR`, converter `--temp-dir`, the `--tmp` dirs of the checks and build caches on disk under `/home/dalibor/programming/personal/dribble.tf-wt/<task>-out/`, never directly in `/home/dalibor/programming/personal/`.
- **Settings reducer**: `UPDATE_SETTINGS_OPTION` runs lodash `set()` on a shallow `clone` of the settings, so nested settings objects (`ui.crosshair`, `ui.nameplate`, `highlander.*`) keep their reference while their fields change. Never wrap a component in `memo`, or memoise on a reference, when it selects a nested settings object. Select primitives, as `useHlSetting` does. `Crosshair` is deliberately not memoized in `DemoViewer.tsx`.
- **Memory rule** (contract 12.3): no module-level variable may hold a parsed demo, an extras object or a store snapshot. Memoise in a `WeakMap` keyed by the extras object or the demo, or in an object a mounted component owns, as F1's `FxFrameCache`, F2's `buildingsAt` and F5's `getHudSnapshot` and `rosterAt` do.
- **Determinism** (D12): everything drawn is a pure function of the extras, the base caches, `renderTick`, `frameProgress` and the settings. Effect logic uses no `performance.now()`, `Date.now()` or `setTimeout`; it animates from `tickF = renderTick + frameProgress`, with `frameProgress` read from `useInstance.getState()` inside `useFrame` and never selected in a component. Seeking to the same tick twice must give identical probe output. Timers outside effect logic, such as the notices' fade-out and the loader's 180 s timeout, are fine. The base `HealBeam` and the legacy projectile smoke animate from wall-clock time, so their pixels differ between runs.
- **Layer rules** (contract 1.6): `React.memo` layers with primitive props; `useExtras()`, which stays undefined until the status is `ready`; per-frame work in `useFrame` through refs; `InstancedMesh` beyond about 20 copies; no network requests and no drei `<Text>`; a check of `extras.meta.available[key]`. HUD numbers come from the shared snapshot at `hudTick`, which steps by `HUD_TICK_STEP` (3) while playing.
- **Data facts**: React code reads the extras with `useExtras()`; `useFrame` code reads `useInstance.getState().extras` after checking `extrasStatus === 'ready'`. `p` is the base player id, from `playerIndexOf(x, entityId)` or `parsedDemo.playerIndexOfEntity`, and every extras position is already in scene space. `RULES.MATCH_ENDED` is always set on serveme servers, so never use it. `misc.obsTarget` stays stale after a respawn, so check `misc.obsMode`. `players.medigun.charge` is stored as charge x 1000. `tempents.tracers.sx/sy/sz` is (999, 999, 999) on sentry tracers, so start them at the drawn barrel (`sentryMuzzleAt`). `positionScale` differs per base cache: parser2 1024, fallback 32.

## Known Highlander limits

- **No game assets** (D1): buildings, every projectile beyond the base viewer's rocket, pipe and sticky models, viewmodels, kits, the payload cart, resupply lockers, prop-door slabs and markers are procedural placeholders. Viewmodels sit behind `ViewmodelProvider` (`src/highlander/scene/viewmodel/provider.ts`), so a GLB provider with priority 10 could replace the placeholders later. The map limits are under "Known visual limits" above.
- **Tickbase lead** (contract 12.2 item 6): `SendPropTime` values that the server writes while it runs a player's user command (`m_flFOVTime`, `m_flChargeBeginTime`, `m_flInvisChangeCompleteTime`) run 3 to 4 ticks ahead of the server tick. The data keeps them unchanged. `povFovAt` in `pov/fov.ts` starts the zoom at `min(m_flFOVTime, entry tick)` for the POV camera and the scope, while `fovAt`, `invisAt` and charge-begin values stay unadjusted; `fovAt` still reads 20 at unzoom + 3.
- **Rare kinds without a local demo**, so unvalidated: jarate (cond 24, projectile kind 11), Mad Milk (27, kind 12), the Quick-Fix uber (28), Vaccinator blast and fire ubers (59, 60), cleavers (14), stun balls (15), Short Circuit orbs (20) and `ClientProjectile_EnergyRing` tempents. Also untested on real data: the minicrit aura (no demo has a MINICRIT rising edge), crit syringes, dropped kit-model items such as the Candy Cane, the arena branch of `TeamMayCapturePoint`, two medics on one team, and left-handed viewmodels, which only `viewmodel.debug` forces. Contract 11.4 lists demos for the rare kinds that do exist.
- **Fallback demos**: with Highlander off, 1429417 and 1428628 still load through the fallback, and saved ticks on 1428628 moved by +3678 (see "Base parser fallback").
- **Newer map versions**: a newer version of a converted map loads the older geometry, and `MapNotice` says "Using <folder> geometry for <map>". Reconvert the new BSP with `npm run convert:bsp`.
- **Smaller limits**: the chase camera has no wall collision. A sentry kill's death camera aims at the engineer, not the sentry. Crit hitscan tracers look like normal ones under additive blending. The declutter thins plates by camera distance only, so tight far clusters still stack, and DOM plates draw over F2's canvas labels. A player model's first appearance compiles its shader, one long task of 120 to 133 ms. Thrown items rest on the bottom of their collision box and can hover a few units on slopes. A bolt stuck in a player who dies disappears. Death markers of deaths on undrawn stock props sit on the prop's top. The KOTH point shows a padlock while waiting for players, as TF2 does. parser2 sizes its timeline by the header, so pauses and cut files end with empty tails.
