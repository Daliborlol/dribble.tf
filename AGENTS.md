# AGENTS.md: operational details for AI agents

## Build & Dev

- **Package manager**: npm (`yarn` not installed; use `npm run build`, `npm run dev`). `node_modules` was installed from the frozen `yarn.lock`, so add or upgrade no dependency, leave `yarn.lock` alone and never create a root `package-lock.json` (contract D15).
- **Worktrees**: link the shared modules once with `ln -s <main checkout>/node_modules <worktree>/node_modules`; the harness creates that link itself on its first run. `/node_modules` in `.gitignore` covers it, and `/scripts/hl/harness/node_modules` covers the harness's own playwright-core. The main checkout holds the harness `node_modules` on this machine, so link `/home/dalibor/programming/personal/dribble.tf/scripts/hl/harness/node_modules` into `<worktree>/scripts/hl/harness/node_modules`.
- **Build**: `npm run build` takes about 13 s (13.2 s with X2's projectile memory module). The main bundle is 2.84 MB on `assets` (2,843 kB; 2.83 MB on `highlander`, 2.81 MB before X2), plus `hlextras_bg.wasm` 3.16 MB and `parser2_bg.wasm` 2.26 MB.
- **Type check**: `node_modules/.bin/tsc --noEmit -p .`. Avoid `npx tsc`, which can fetch an unrelated npm package named `tsc`. Exactly 10 errors are pre-existing and allowed: `BuildingCache.ts` x4, `ChunkedArray.ts` x3, `AnalyseMenu.tsx`, `DemoDrawing.tsx` and `UrlDemoNotice.tsx`. Any other error is new. `tsconfig.json` excludes `src/libs`, the wasm-bindgen glue.
- **Dev server**: `npm run dev` (Vite). It always installs the debug bridge `window.__dribble`; other builds install it only with `?debug=1`.
- **Converter config precedence**: `scripts/convert-config.json` overrides `scripts/convert-map.mjs` defaults when present, so map-conversion verification should pass explicit CLI flags or update the config if testing a changed default such as `chunk-grid`
- **Converter validation reruns**: pass `--chunk-grid 8` explicitly while `scripts/convert-config.json` still pins `chunk-grid=4`; `--skip-material-truth true` skips the slow VPK material scan when validating chunking/visibility output
- **Converter resume path**: `node scripts/convert-map.mjs ... --metadata-only true` reuses the temp BSP/VMF/GLBs/lightmaps to finish skybox, teleports, visibility, and `conversion.json` after a late-stage failure; skybox conversion still needs `vtf2img` importable from the `python3` on `PATH`
- **Headless browser validation**: use the harness in `scripts/hl/harness/`, described under "Highlander validation tools". It launches the Playwright Chromium headless shell of the revision its playwright-core expects (1248) and renders WebGL on this machine's iGPU through ANGLE EGL (`--use-gl=angle --use-angle=gl-egl --enable-gpu --enable-webgl --ignore-gpu-blocklist`). When the renderer string says SwiftShader or WebGL2 is missing, it relaunches with SwiftShader (`--use-angle=swiftshader --enable-unsafe-swiftshader`), which draws the app on the CPU at 1 to 6 fps. A Chrome you drive yourself over remote debugging needs both `--user-data-dir=<tmp>` and `--remote-allow-origins=*`. `?perf=true` enables runtime perf logs.
- **WASM support**: Vite 5 handles `.wasm` via `new URL('./file.wasm', import.meta.url)` natively. No `vite-plugin-wasm` or `vite-plugin-top-level-await` is needed; wasm-bindgen's JS glue uses this pattern and has its own MIME-type fallback
- **Framework**: React + Three.js (react-three-fiber) + Zustand + Tailwind

## Highlander (9v9) mode

- **What it adds**: a second parse of each demo, the extras, feeds Highlander layers drawn on top of the base viewer. Players show cloak, decloak and disguises, uber, crit and debuff effects, crouching and the weapon they hold. Engineers get sentries, dispensers, teleporters and sappers. Every projectile type flies, with crit glows, explosions, tracers, flames and airblast, and sniper and wrangler dots draw.
- **POV and HUD**: POV gets the TF2 FOV and zoom, a scope overlay, class eye heights, viewmodels, a weapon HUD, death cameras and a chase camera. The HUD gets an objective panel for KOTH, payload, control points, stopwatch and tug of war, 9v9 player columns with badges, a medic panel, a Tab scoreboard, killfeed icons, a round banner and timeline markers. On the map, doors and trains move, kits show respawn rings, thrown lunchbox items fly and deaths leave markers. Without a pack everything Highlander adds is procedural placeholder geometry. Asset contract D1 (`specs/assets/contract.md` 1.1) replaces Highlander D1: no Valve asset goes into git or the default deploy, and real TF2 content beyond the pre-existing upstream files comes only from a local pack the user built (see "Asset pack"). After wave 3 that is textured maps and props and the models of buildings, extras projectiles, map items, the cart and viewmodels; without a pack, and for the weapons the pack lacks, the viewmodels are placeholders.

- **Extras pipeline**: the base parse stays the committed `src/libs/parser2` binary, which is never rebuilt because its source is unpublished (D2). After the base parse resolves, its worker ends and the scene loads, `parseDemoAction` takes the file buffer the base worker handed back (`parsedDemo.takeFileBuffer()`) and calls `startHighlanderExtras` in `extras/loadExtras.ts`. `ExtrasWorker.ts` loads the second wasm module `src/libs/hlextras`, built from `../dribble-parser` branch `highlander`. It copies the file into wasm memory (`ExtrasInput`), detaches the JS buffer and calls `parse_demo_extras_input` with the base parse's `startTick`, `tickBase`, `ticks`, `intervalPerTick` and `playerEntityIds`, so the extras share the base cache ticks and player indices by construction (D3).
- **Hydration and alignment**: `hydrate.ts` moves every position into scene space (Source minus `parsedDemo.world.boundaryMin`) and builds the `HL` flag masks and the per-player and per-entity indexes. The main thread runs `checkAlignment` (16 sample ticks, base and extras positions within 4 units) and then stores the result as `useInstance().extras` with status `ready`, or sets status `error` with `misaligned: <reason>`. No result after 180 s is an error too. Loading a new demo cancels a running extras parse first, so the two parses never overlap (D4). When that new load then fails, the demo still shown ends at status `error` ("cancelled by the failed load of another file; reload the demo"), not stuck at `loading`.
- **Extras cost**: on 1438891 (koth_product, 817 s, 50 MB) the extras parse takes about 1.1 s in the browser and holds 9.9 MB of typed arrays. On 1429417 (130k ticks) it takes 2.7 s and holds 39 MB, with a 213 MB wasm heap that ends with its worker.
- **Memory plan**: `extras/memory.ts` predicts the worker peak as `1.6 x fileMB + 126` MiB against `EXTRAS_BUDGET_MB` 600, or 300 when `navigator.deviceMemory` is at most 4. Over budget it drops optional groups by measured size, largest first: `drops`, `movers`, `flames`, `tempents`, `ragdolls`, `pickups`. It never drops `players`, `objectives`, `buildings` or `projectiles`, and when nothing fits it skips the extras ("demo too large for Highlander data on this device"). The largest local demo (123 MB) predicts about 322 MiB, so the default budget excludes nothing locally. `?hlExtrasBudget=<MB>` replaces the budget, and `?hlExtrasBudget=1` forces the skip path.
- **Base projectile release** (X2): parser2 and the fallback store a position and a rotation for every projectile slot at every tick, although a slot holds a projectile at only 0.1 to 1.3 % of its ticks, so the base projectile cache takes 205 MB on 1438891 and 641 MB on 1429417. `memory/projectileMemory.ts` releases it once per demo. It checks on every store update whether the extras are `ready` with `meta.available.projectiles` true, `settings.highlander.enabled` is on and the demo is still the loaded one. Then it waits for an idle period of the main thread, at most 2 s (`requestIdleCallback`, or `setTimeout(0)` where that is missing), and checks again. The release computes F3's split, copies every base row into a `ProjectileAdapter` and compares the copy with the cache: 256 spread ticks, the first and last tick, and for every track the slot's row one tick before it, at its first and last tick and one tick after it. Then `AsyncParser.releaseProjectileCache(adapter)` empties the four typed caches and detaches their buffers with `ArrayBuffer.transfer(0)`. All of it takes 13 to 41 ms on the measured demos, and the console logs `[HL] base projectile cache released` with the sizes and `phaseMs`. The adapter is an exact copy of 0.4 to 4.1 MB: raw fixed-point positions and rotations plus the bucket team and type, decoded with the cache's own scales, so readers get the same numbers in the same order. It serves every base projectile read for the rest of the session, also with Highlander off and after an extras restart, reload or error (see "Reading base projectiles" under Gotchas). The cache stays as long as the extras are not ready: while they load, after they fail, and until the next demo load when they never run because Highlander was off at load or the memory plan skipped the file. It also stays while Highlander is off, when `projectiles` is excluded or empty, and when the build or the self-check fails, which logs `[HL] base projectile cache kept: <reason>` and is not retried for that demo. `?hlProjectileRelease=manual` keeps the cache until the probe `memory.release` asks.
- **Toggle**: `settings.highlander.enabled`, the "Highlander features (applies on next demo load)" row. Its value at demo load decides whether the extras parse runs; when it is off, the status is `disabled`. Everything else follows the switch at once. Off unmounts every Highlander layer and widget and brings back the pre-Highlander player list, killfeed, POV camera with the legacy eye height of 83, and plain nameplates without the cap. On mounts them again, but a demo loaded while the switch was off has no extras, so until the next load it gets only what runs from base data (next bullet). The base-parse fallback described below runs either way. The other keys come in seven groups, `players`, `buildings`, `projectiles`, `sniper`, `pov`, `hud` and `map`, listed under "Highlander settings".
- **Highlander on without extras**: while `enabled` is true and the extras are not ready, the HUD and POV keep their Highlander form and read the base caches. That covers the extras load itself, an extras error, a memory-plan skip and a demo loaded with the switch off; `?hlExtrasBudget=1` reproduces it.
  - HUD: `HudLayout` picks the 9v9 layout from the switch alone. The player columns show class, health and the base respawn countdown without badges, and their hover titles carry K, A and D from base deaths. The medic panels show the base uber charge under the name "Medigun", and the killfeed is the Highlander one, built from base deaths. Nothing marks Dead Ringer feigns without extras, so the killfeed and the scoreboard count them as kills and deaths. The scoreboard footer says so, "K and D from base deaths, Dead Ringer feigns included" (with extras kill events it says "K and D without Dead Ringer feigns"), and it names a damage source only when there is one. The objective HUD, round banner, scope overlay, weapon HUD and timeline markers need extras and stay empty.
  - POV: `pov.tf2Fov` sets TF2's 90 degrees horizontal at 4:3, 73.74 vertical, with near plane 1 and no zoom. `pov.eyeHeight` gives the class eye height, or 45 while the base duck bit is set, instead of the legacy 83. After a death, `pov.deadPov` 'spectated' holds the camera at the death spot, facing where the player looked one tick before, until he respawns. `povSubjectAt` turns to the killer or a spectated teammate only with the extras' observer data.   - Elsewhere: the 12-plate cap and `players.nameplateFadeDistance` apply, and `projectiles.explosions` off hides the base despawn explosions. Scene layers, nameplate extras and the crouch scale wait for the extras.

## Highlander settings

`settings.highlander` is defined in `src/highlander/settings.ts`. The Settings panel's "Highlander" section writes every key through `updateSettingsOptionAction('highlander.<path>', value)`, saved settings merge into new defaults (lodash `merge` in `loadSettingsAction`), and the debug bridge sets them with `setSetting('highlander.<path>', value)`. Read one value in React with `useHlSetting('players.cloak')` and elsewhere with `getHlSetting`.

- `enabled` = true: the master switch, see Toggle above.
- `players.conditions` = true: master toggle of the four effect groups below, not of cloak and disguise.

Players: `listPlayers(tick?)`, `resolvePlayer(query)` and `focusPlayer(query)`, where a query is an entity id, a class such as `sniper` or `sniper@red`, or a name. Cameras: `setControlsMode('rts' | 'spectator' | 'pov', { player?, reset? })`, `getCamera()` and `setCamera(spec)`. Settings: `setSetting(dottedPath, value)`. - **Probe rules**: `runHlProbe` never throws, and an unknown name or a thrown error comes back as `{ error }`. These need arguments: `fx.actor(entityId)`, `buildings.of(p)`, `buildings.track(instance, from, to)`, `buildings.tracerMuzzle(row)`, `pov.wallScan(p, from, to)`, `extras.call(getter)` and `extras.restart(url)`. Called without them in a sweep, `fx.actor` and `buildings.tracerMuzzle` return errors by design, and `map.props` carries a field `error: null` that is not an error.
- **Side effects and slow probes**: `extras.restart` fetches the demo again and restarts the extras parse. `viewmodel.debug` keeps its overrides until they are set back. `nameplates.cap(false)` turns the 12-plate cap off for the page. `mapdyn.surface(true)` re-runs both floor analyses synchronously. `pov.wallScan` and `pov.wallDistance` cast map rays without a BVH, and `buildings.summary()` scans every tick. `memory.release` releases the base projectile cache, which never comes back for that demo, and `memory.digest()` reads every tick: 0.1 to 0.5 s on the cache, under 0.07 s on the adapter. A sweep over `hl.probes()` should skip these, `extras.call`, `assets.modelShow` and `assets.waitIdle`, which the harness awaits itself, as the sweep in `scripts/hl/harness/plans/smoke-gen.mjs` does.
- **findTicks**: `extras/findTicks.ts` knows 59 kinds (`FIND_KINDS`) plus `proj:<kind>`. It returns cache ticks in ascending order as `{ tick, player?, instance?, note? }`. `limit` defaults to 20, `player` (index p) and `team` (2 RED, 3 BLU) filter, and an unknown kind returns `[]`.
  - spy: `cloak` (`note: 'feign'` on Dead Ringer cloaks), `decloak`, `disguise`, `disguising`, `feign`, `backstab`, `headshot`
  - medic: `uber` (stock or unknown Medi Gun only), `kritz`, `quickfix`, `vacc`, `medicDrop`, `medicCall`
  - conditions: `crit`, `minicrit`, `burning`, `jarate`, `milk`, `marked`, `bonk`, `overheal`, `teleportedGlow`, `stun`, `gas`, `banner`, `zoom`
  - combat: `busiest`, `airblast`, `flamesOn`, `deflect`, `proj:<kind>` (`proj:7` flares, `proj:8` arrows, ...), `syringe`, `explosion`, `tracer`, `bullet`, `critBullet`
  - engineer: `buildStart`, `buildDone`, `upgrade`, `carry`, `redeploy`, `sapped`, `destroyed`, `teleported`, `wrangled`
  - objectives: `capStart`, `captured`, `capBlocked`, `capBroken`, `capping` (crossings of 0.5 progress), `cartMoving`, `cartReceding`, `overtime`, `roundWin`, `roundStart`, `setupFinished`, `respawnWave`
  - map: `doorMove`, `pickupTaken`, `pickupBack`. A `pickupTaken` row is one of two kinds of take. A map kit that leaves the snapshot (a `pickups.vis` falling edge) is a take, except a deletion at a round restart or a kit that leaves for good. A thrown or dropped item deleted on the tick of an `item_pickup` event of its kind is a take too, with `note: 'thrown'`. `player` names the taker when exactly one such event matches the tick and kind.
  - Kinds are not memoised, so cache results per extras object. `findTicks('busiest')[0]` is the earliest of the busiest windows, not the busiest one.
- **In plans and evals**: actors move 2 to 5 frames after `goToTick`, so `await window.__dribble.frames(5)` before reading scene nodes. Early steps can run before the player GLBs load (`actors.registry` reports `modelVisible: null`), so poll. A camera set with `setCamera` survives later steps, and `setControlsMode('rts', { reset: true })` does not restore the default RTS camera while the controls are already in RTS, so come from a POV step. An eval can switch the POV player itself with `await window.__dribble.setControlsMode('pov', { player: entityId })`. The automatic projectile release comes at most 2 s after the extras are ready, and headless runs measured 1.5 to 2.0 s, because a rendering canvas leaves Chromium little idle time. A step that reads `memory.projectiles` right after `waitReady` can see `pending`, so wait 2.5 s, or load with `?hlProjectileRelease=manual` and call `memory.release`.

## Highlander validation tools

- **Harness** (H1): `scripts/hl/harness/`, with `README.md` as the reference for every option, the plan and manifest formats, the GPU backends and the known noise. `shot.mjs` builds a checkout with vite into a build cache, serves the build and a local demo on 127.0.0.1, opens the viewer with `?debug=1` in headless Chromium, runs each plan step through `window.__dribble` and writes `NN-<name>.png`, `manifest.json` and `console.log`, plus `perf.json` with `--perf-play`. It always shuts down its server and browser, and it needs Linux and Node 20 or newer. The Highlander tasks ran a session scratchpad copy of it; the README's "Changes from the scratchpad copy" lists the differences.
- **Harness setup**: `npm install --prefix scripts/hl/harness --no-package-lock` installs playwright-core 1.64.0 into `scripts/hl/harness/node_modules`, which git ignores; the app's dependencies and `yarn.lock` stay as they are. A worktree without that folder uses the main checkout's, or link an existing one into it. The harness picks the `chromium_headless_shell-1248` that playwright-core expects, else `chromium-1248`, else the newest headless shell and then the newest chromium, and in those last two cases it warns in the log, in `--check` and in the manifest's `warnings`. `--browser shell|chrome|<path>` or `CHROME_PATH` choose another. `node scripts/hl/harness/shot.mjs --check --demo <demo.dem>` prints the resolved root, build cache, lock, playwright-core and browser, and exits 1 with the fix for anything missing.
- **Running it**: `node scripts/hl/harness/shot.mjs --root <worktree> --demo /home/dalibor/demo_tool/demos/<id>.dem --plan <plan.json> --lock <lock> --build-cache <task-out>/builds --out <task-out>/<run>`. Without `--plan` it shoots `--ticks 10%,50%,90%` in `--modes rts,pov` with `--pov auto`. A plan is a JSON array of steps with the optional fields `name`, `tick` (a playback tick or a percentage), `mode`, `player`, `reset`, `settings`, `speed`, `camera`, `play`, `eval`, `hideHud` and `screenshot`. The harness awaits a promise that an `eval` returns and stores its JSON in the manifest. `--perf-play tick:seconds[:mode[:player[:speed]]]` measures fps, frame times, long tasks and memory, and `--cpu-profile --no-minify` adds a CPU profile with readable names. `--help` lists all 35 options, among them `--trace` (a Chromium trace of the `--perf-play` seconds with busy ms per frame per thread and event in `perf-trace.txt`: renderer main, compositor, GPU process main), among them `--asset-pack <dir|missing>` and `--no-vsync` (see "Asset pack"), `--size 1600x900`, `--hide-hud`, `--query a=b` (repeatable), `--init-script <file>`, `--gpu egl|vulkan|swiftshader`, `--min-available <MB>` with `--wait-available <s>`, `--rebuild` and `--no-build`. Exit 0 means the run finished, with any failed step in the manifest's `warnings`; 1 is a setup or load failure, 2 a usage error, 75 a closed memory gate (nothing ran), 124 the hard timeout (`--timeout`, 900 s) and 130 an interrupt.
- **Lock, build cache and output**: the harness re-runs itself under `flock <lock>` and recognises an outer `flock` on the same file. Its default lock, `<os.tmpdir()>/dribble-heavy.lock`, follows `TMPDIR`, so agents that share the machine pass the shared lock with `--lock` or `DRIBBLE_HARNESS_LOCK`. The build cache defaults to `<root>/node_modules/.cache/dribble-harness` (`DRIBBLE_HARNESS_BUILDS`), which in a worktree resolves into the main checkout's `node_modules` through the link. It keeps one entry of about 8.5 MB per checkout path and rebuilds, in about 13 s, when a file under `src/` or a root config file changes. `--out` defaults to `<root>/../<root name>-harness-out/<demo>-<UTC time>`, which for the main checkout lands directly in `/home/dalibor/programming/personal/`. So pass `--build-cache` and `--out` under `/home/dalibor/programming/personal/dribble.tf-wt/<task>-out/`, as the `/tmp` quota under Gotchas says.
- **Baseline and smoke plans**: `scripts/hl/harness/plans/1438891-baseline.json` is the 15-step baseline plan on koth_product. `node scripts/hl/harness/plans/smoke-gen.mjs <dir> [plan ...]` writes `smoke-<demo>.json` for 1438891, 1434434, 1440442, 1429417, 1428628 and the 6v6 `sample`: a probe sweep, RTS and POV shots and probe reads. `node scripts/hl/harness/summarize.mjs <run dir | manifest.json>` prints the load state, memory, warnings, one line per step and the console's error lines.
- **Comparing two runs**: `node scripts/hl/harness/tools/compare-runs.mjs <refRun> <newRun> [outDir] [--max-pct p]` is the baseline gate. It exits 0 when both runs did the same thing: the same demo header, viewport and manifest structure, and for every step the same definition, tick, camera mode, focused player, error and screenshot, plus the same render tick and player list for steps without `play`, which run on wall time. It exits 1 when something differs or a shot changed more than `--max-pct`, and lists each reason under `result:` and in `compare.json`; 2 means the runs could not be compared, and 64 is a usage error. Since the asset phase it also compares the request logs (`requests` in the manifest) by the request-set rule of asset contract 5.1: pathnames only, the content hash of `/assets/` build files normalised to `-[hash]`, keys counted, so a `src/` change that renames every bundle still compares equal. A difference fails as `requests differ: <key> <countA> -> <countB>`; `--allow-request <key>` (repeatable) accepts one key. Eval, browser, WebGL renderer, pack fingerprint and console differences only print warnings. Pixels still need a person. It writes `<name>-diff.png` for every changed shot and `sheet.png` with A, B and the diff, and a pixel counts as changed when a channel moves by more than 24 of 255. Open every shot above about 0.01 %. Heal beams, the ÜBER READY pulse and the FPS counter change between runs of one build, by up to 0.64 % per baseline shot and 1.7 % when a beam passes close to a POV camera. `tools/imgdiff.mjs <dirA> <dirB> <outDir> [threshold]` is the pixel diff alone and `tools/sheet.mjs` tiles a contact sheet; scripts import `diffPng` and `diffDirs` from `lib/images.mjs`.

## Base parser fallback

- **Why**: the committed `src/libs/parser2`, which is never rebuilt, starts its cache only after 100 warmup packets with non-zero world bounds. If the fallback of a delayed start fails, parser2 parses the file once more (`{ lateStart: true }`) and the demo loads with parser2's late timeline; `parserFallbackFailure` records the error and `parserFallback` stays false. - **Build guarantees**: stages write into a staging folder; the builder validates the new manifest and every listed file before the first rename, moves files by atomic renames and writes `manifest.json` last, so a failed or interrupted build leaves the previous pack working. Builds are incremental by input key (VPK fingerprint, `GENERATOR_VERSION`, BSP sha256, the public `conversion.json` values used, a hash of the converter sources and the bsp-to-glb version); `--force` rebuilds everything, and entries of stages that do not run carry over. Two builds of the same inputs are byte-identical: `node scripts/assets/check-determinism.mjs <packA> <packB>` compares file lists and sha256 and exits 1 with the differing files.

## Gotchas

- **Never push**: no `git push` anywhere, to any remote. This is a standing user rule. In multi-agent runs the main checkouts of `dribble.tf` and `../dribble-parser`, both on `highlander`, belong to the orchestrator, so work and commit in your own worktree and branch.
- **Unsigned commits**: gpg signing fails in this environment, so commit with `git -c commit.gpgsign=false commit`, end the message with the attribution line the session gives, and tell the user. `specs/highlander/STATUS.md` has the commands to re-sign later.
- **Heavy commands under one lock**: while several agents share the machine, run cargo and wasm-pack (with `CARGO_BUILD_JOBS=4`), `npm run build`, tsc, Node parses of demos, Chromium and dev-server sessions as `flock <lock file> <command>`. Call flock directly, because a flock around `bash -c` trips a Claude Code safety check. The harness takes the lock itself when it gets the shared file through `--lock` or `DRIBBLE_HARNESS_LOCK`. Never hold the lock while idle, and kill any server or browser you start. `/usr/bin/time` is not installed.
- **Memory gates**: swap is full, so check `free -m` first. Runs on 1428628, 1429417 and the long demos (1437285, 1432698, 1433815) need at least 3000 MB available; the harness checks that inside the lock with `--min-available 3000 --wait-available <s>`. parser2 in Node peaks at 2.3 GB on 1433815.
- **/tmp quota**: `/tmp` is a tmpfs with a per-user quota of about 5 GB that every agent shares. It filled before, and EDQUOT broke builds and lost Bash output. Put harness outputs and build caches (`--out`, `--build-cache`), `TMPDIR`, converter `--temp-dir` and the `--tmp` dirs of the checks on disk under `/home/dalibor/programming/personal/dribble.tf-wt/<task>-out/`, never directly in `/home/dalibor/programming/personal/`.
- **Settings reducer**: `UPDATE_SETTINGS_OPTION` runs lodash `set()` on a shallow `clone` of the settings, so nested settings objects (`ui.crosshair`, `ui.nameplate`, `highlander.*`) keep their reference while their fields change. Never wrap a component in `memo`, or memoise on a reference, when it selects a nested settings object. Select primitives, as `useHlSetting` does. `Crosshair` is deliberately not memoized in `DemoViewer.tsx`.
- **Memory rule** (contract 12.3): no module-level variable may hold a parsed demo, an extras object or a store snapshot. Memoise in a `WeakMap` keyed by the extras object or the demo, or in an object a mounted component owns, as F1's `FxFrameCache`, F2's `buildingsAt`, F5's `getHudSnapshot` and `rosterAt` and X2's release records do.
- **Determinism** (D12): everything drawn is a pure function of the extras, the base caches, `renderTick`, `frameProgress` and the settings. Effect logic uses no `performance.now()`, `Date.now()` or `setTimeout`; it animates from `tickF = renderTick + frameProgress`, read inside `useFrame` with `frameTime()` (`combat/time.ts`), which takes the tick and `frameProgress` from the store in the same frame. Never select `frameProgress` in a component, and never add it to a `renderTick` prop: DemoViewer sets both in one animation frame, but the prop reaches React a frame later, so the sum steps back at tick boundaries (judder below 1x and on high-refresh screens). Every interpolating Highlander scene layer reads it this way since `hl/fix-ticksync2`. `frameTime()` adds `frameProgress` only while playing with `scene.interpolateFrames` on, so with it off these layers snap to whole ticks like the actors. Seeking to the same tick twice must give identical probe output. Timers outside effect logic, such as the notices' fade-out, the loader's 180 s timeout and the 2 s bound on X2's idle-time release, are fine; the release serves the same rows before and after. The base `HealBeam` and the legacy projectile path, which draws with Highlander off and until the extras are ready, depend on wall-clock time, so their pixels differ between runs. The legacy path smooths positions over 50 ms of frame time and times smoke, trails and despawn explosions with `performance.now()`.
- **Layer rules** (contract 1.6): `React.memo` layers with primitive props; `useExtras()`, which stays undefined until the status is `ready`; per-frame work in `useFrame` through refs; `InstancedMesh` beyond about 20 copies; no network requests and no drei `<Text>`; a check of `extras.meta.available[key]`. HUD numbers come from the shared snapshot at `hudTick`, which steps by `HUD_TICK_STEP` (3) while playing.
- **Scene matrices** (as/perf): the `world` group has `matrixAutoUpdate` false, so code that moves it must call `updateMatrix()` (World.tsx does on mount and on a bounds change); frozen map leaves have `matrixWorldAutoUpdate` false and update only when an ancestor moves. A group that composes its matrix every frame forces three to recompute its whole subtree every frame. `PackPlayer` installs a `scene.onBeforeRender` hook (chained) for its view culling.
- **GPU disposal**: react-three-fiber 8.18 frees the objects of removed JSX (`<instancedMesh>`, `<sphereGeometry>`, inline materials) only from an idle-priority scheduler task that never runs in this app, so every remount strands their GPU buffers. Create such objects in `useMemo`, render them with `<primitive object={...} />` or pass them as props, and dispose them in an effect cleanup, or share one module-level geometry and material, as `useInstancedMesh`, `HealBeam` and the legacy projectile components do. Check a change with `renderer.info.memory` over a few demo reloads and mode switches; the counts should stay flat.
- **Forced map switches**: setting `scene.map` to a map other than the loaded demo's own loads empty `world.glb` and `props.glb` roots, already on `a06e4c7`. Measure map and props behaviour (GPU memory, prop counts) on a demo of that map instead. Textures in `renderer.info.memory` grow by 2 per map reload with and without the pack (pre-existing).
- **Data facts**: React code reads the extras with `useExtras()`; `useFrame` code reads `useInstance.getState().extras` after checking `extrasStatus === 'ready'`. `p` is the base player id, from `playerIndexOf(x, entityId)` or `parsedDemo.playerIndexOfEntity`, and every extras position is already in scene space. `RULES.MATCH_ENDED` is always set on serveme servers, so never use it. `misc.obsTarget` stays stale after a respawn, so check `misc.obsMode`. `players.medigun.charge` is stored as charge x 1000. `tempents.tracers.sx/sy/sz` is (999, 999, 999) on sentry tracers, so start them at the drawn barrel (`sentryMuzzleAt`). `positionScale` differs per base cache: parser2 1024, fallback 32.
- **Reading base projectiles** (X2): read them through `demo.getProjectilesAtTick(tick)` or `demo.projectileReader()`, never through `demo.projectileCache`. After the release that field still holds the cache object, but its arrays are empty, so a direct read finds no projectiles instead of failing. The adapter is then the only source for the rest of the session. It serves every `CachedProjectile` field and `getTypeCode`, holds its own copy and no demo, extras or store reference, and lives on the demo, so any later extras object can use it. A new reader that needs anything else from the base projectile arrays has to stop the release in `memory/projectileMemory.ts` and record why (contract 13.4).

## Known Highlander limits

- **No game assets** (Highlander D1, replaced by asset contract D1): without a pack, buildings, every projectile beyond the base viewer's rocket, pipe and sticky models, viewmodels, kits, the payload cart, resupply lockers, prop-door slabs and markers are procedural placeholders. With a pack, buildings, extras projectiles (not gas, energy rings and balls, fireballs or orbs), kits, plates, ammo, drops, lockers, the cart and viewmodels draw TF2 models, and maps and props draw textured; prop-door slabs and markers stay placeholders. Viewmodels go through `ViewmodelProvider` (`src/highlander/scene/viewmodel/provider.ts`): the GLB provider at priority 10 draws the pack's arms and weapons, and the placeholder provider covers the minigun family, weapons the pack lacks, old demos without local tables and every case without a pack. The map limits are under "Known visual limits" above.
- **Tickbase lead** (contract 12.2 item 6): `SendPropTime` values that the server writes while it runs a player's user command (`m_flFOVTime`, `m_flChargeBeginTime`, `m_flInvisChangeCompleteTime`) run 3 to 4 ticks ahead of the server tick. The data keeps them unchanged. `povFovAt` in `pov/fov.ts` starts the zoom at `min(m_flFOVTime, entry tick)` for the POV camera and the scope, while `fovAt`, `invisAt` and charge-begin values stay unadjusted; `fovAt` still reads 20 at unzoom + 3.
- **Rare kinds without a local demo**, so unvalidated: jarate (cond 24, projectile kind 11), Mad Milk (27, kind 12), the Quick-Fix uber (28), Vaccinator blast and fire ubers (59, 60), cleavers (14), stun balls (15), Short Circuit orbs (20) and `ClientProjectile_EnergyRing` tempents. Also untested on real data: the minicrit aura (no demo has a MINICRIT rising edge), crit syringes, dropped kit-model items such as the Candy Cane, the arena branch of `TeamMayCapturePoint`, two medics on one team, and left-handed viewmodels, which only `viewmodel.debug` forces. Contract 11.4 lists demos for the rare kinds that do exist.
- **HUD and POV without extras**: with Highlander on, the 9v9 HUD, TF2's POV FOV, class eye heights and the nameplate cap run from base data before the extras arrive and when they never do (see "Highlander on without extras"). Contract 14.2 accepts this in place of 3.9's "base UI only".
- **Projectile memory without extras**: X2 releases the base projectile cache only once the extras serve projectiles, so a demo loaded with Highlander off, skipped by the memory plan or left with an extras error keeps all of it: 205 MB on 1438891, 641 MB on 1429417.
- **Fallback demos**: with Highlander off, 1429417 and 1428628 still load through the fallback, and saved ticks on 1428628 moved by +3678 (see "Base parser fallback").
- **Newer map versions**: a newer version of a converted map loads the older geometry, and `MapNotice` says "Using <folder> geometry for <map>". Converting the new BSP is not enough on its own: its exact name also needs a `MAP_NAME_SEARCH_MAP` key, as "Newer version of a converted map" under Maps describes.
- **Smaller limits**: the chase camera has no wall collision. A sentry kill's death camera aims at the engineer, not the sentry. Crit hitscan tracers look like normal ones under additive blending. The declutter thins plates by camera distance only, so tight far clusters still stack, and DOM plates draw over F2's canvas labels. A player model's first appearance compiles its shader, one long task of 120 to 133 ms. Thrown items rest on the bottom of their collision box and can hover a few units on slopes. A bolt stuck in a player who dies disappears. Death markers of deaths on undrawn stock props sit on the prop's top. The KOTH point shows a padlock while waiting for players, as TF2 does. parser2 sizes its timeline by the header, so pauses and cut files end with empty tails. The base `console.log(parsedDemo)` in `parseDemoAction` (`src/zustand/actions.ts`, older than Highlander) keeps every loaded demo and its extras alive while devtools or a console capture holds the logged object, so measure memory across reloads without one.

## Project structure

- `src/utils/parser.ts`: duration and tick utilities
- `src/components/Analyse/Data/`: demo parsing (ParseWorker, AsyncParser, PlayerCache, ProjectileCache); `ProjectileCache.ts` also defines `ProjectileReader`, which X2's adapter in `src/highlander/memory/` implements
- `src/components/Scene/`: 3D scene rendering (World, Actors, Projectiles, Skybox, Lights)
- `src/highlander/`: Highlander mode, see "Highlander (9v9) mode"
- `src/libs/parser2/`: the base parser, a committed binary that is never rebuilt; `src/libs/hlextras/`: the extras parser and the fallback cache builder, rebuilt from `../dribble-parser`
- `src/utils/debugBridge.ts`: `window.__dribble`
- `src/assetpack/` (alias `@pack/*`): the asset pack runtime; `scripts/assets/`: the pack builder; `specs/assets/`: `contract.md` (asset contract, v1.3) and `STATUS.md`
- `src/utils/mapAssets.ts`, `src/highlander/map/`: map folder lookup, cached `conversion.json`, `map-meta.json` loader, brush-entity nodes, bsp-to-glb materials, PAK props
- `scripts/convert-bsp.mjs`, `scripts/lib/map-meta.mjs`, `scripts/lib/static-props.mjs`, `scripts/setup-bsp-to-glb.mjs`, `scripts/bsp-to-glb/*.patch`: BSP to map package converter
- `scripts/hl/`: Highlander checks, expectations and surveys; `scripts/hl/harness/`: the headless validation harness; `scripts/build-items.mjs`: `src/constants/items.json`
- `specs/highlander/`: `contract.md` (the binding implementation contract, version 2.4; section 14 overrides older text), `STATUS.md` (what is done and what is not), and the research docs `parser-probe.md`, `maps.md`, `tf2-reference.md` and `frontend.md`
- `src/components/DemoViewer.tsx`: main playback engine
- `src/components/UI/`: UI panels (PlaybackPanel, SettingsPanel)
- `src/zustand/store.ts`: global state store `useStore`, plus the instance store `useInstance` that holds the parsed demo, the extras and other non-serialisable state
- `public/models/players/`: player model GLB files
